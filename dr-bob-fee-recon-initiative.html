⏱️ Today's Manual Process — Step by Step

The 6–10 Step Byte Scavenger Hunt

  1. Navigate to DOCS tab — identify correct Final CD among duplicates
  2. Download Final CD — note fee amounts (location varies by doc and county)
  3. Navigate to POST CLSNG tab — find Post-Closing CD if present
  4. Navigate to DOCS tab — find Final Settlement Statement, confirm version
  5. Navigate to PROP tab — locate Recorded Warranty Deed
  6. Navigate to POST CLSNG tab — locate Recorded DOT / Security Instrument
  7. Manually compare Government Recording Fees across all documents
  8. If docs missing → Parties screen → email Settlement Agent → wait for response
  9. Sign checklist — reviewer initials only, no timestamp, no defensible audit trail

The Compliance Risk

When Government Recording Fees on the CD do not match what was actually recorded, a borrower refund is legally required under RESPA. At CMG's volume, the manual process cannot reliably catch every mismatch. One missed finding is a regulatory exposure.

⚙️ End-to-End Pipeline — How It Actually Works

Step 1 — Auditor Initiates in BoB

User selects loan number, selects "Fee Reconciliation" bundle type. BoB queries BytePro API, auto-identifies the approved version of each document across all Byte tabs. No manual hunting.

Step 2 — BoB Assembles The Big 3

PDF bundle assembled in configured stacking order, delivered to internal server in under 15 seconds. Before Dr. BoB is even built, this step alone eliminates the 6–10 manual Byte steps.

Step 3 — Dr. BoB OCRs in Stacking Order

Because the stacking order is known and deterministic, Dr. BoB knows exactly what document is at every position before opening the file. Structured, rule-driven extraction — not guesswork. Reliable at any volume.

Step 4 — 4-Rule Cross-Reference

R1: CD vs FSS. R2: FSS vs Warranty Deed. R3: FSS vs DOT. R4: Bundle completeness. Two-phase model: docs vs. docs first, then BytePro system-of-record confirmation.

Step 5 — Exception-Only Notification

Findings email to initiating user + fee-recon@cmgfi.com. Passing loans: no email. Flagged loans: field-level detail (extracted value vs. expected) with remediation path. Timestamped audit log — every loan, every time.

⚖️ The 4 OCR Validation Rules — Full Detail

R1 CD vs. Final Settlement Statement

Extract Government Recording Fees from Final CD (Doc 1) and Final Settlement Statement (Doc 4). All line items must match. Mismatch → "Inaccurate fee disclosure to borrower."

R2 FSS vs. Recorded Warranty Deed

Extract recording fee from FSS (Doc 4). Extract fee stamp from Recorded Warranty Deed (Doc 5) — top-right first page, bottom of last page, or attached recording page. Mismatch → "Borrower may have been overcharged. Refund legally required."

R3 FSS vs. Recorded DOT / Security Instrument

Extract recording fee from FSS (Doc 4). Extract fee stamp from DOT (Doc 6) — right corner or attached recording page. Mismatch → "Borrower may have been overcharged. Refund legally required."

R4 Bundle Completeness Check

All required documents must be present before OCR begins. Missing doc → "Request from Settlement Agent via Parties screen in Byte." Missing = incomplete reconciliation — not a pass.

Two-Phase Validation Model

  • Phase 1: Intra-bundle cross-reference — docs vs. docs (Rules R1–R4)
  • Phase 2: System of record confirmation — extracted values vs. BytePro DB (final gate)

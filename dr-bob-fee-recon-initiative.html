❌ The Current Workflow

  • Navigate to Byte Stored Documents — 3 separate tabs
  • Identify which version is the recorded document (multiples exist)
  • Download 6 documents individually
  • Locate fee amounts — buried on first page, last page, or attached page (varies by county)
  • Manually compare values across all docs line by line
  • If docs missing → Parties screen → email Settlement Agent → wait
  • If fees don't match → determine refund required → notify Title Company

💸 The Cost of the Current Process

  • Significant auditor time per loan at scale
  • High miss rate — stare-and-compare fatigue is real
  • No automated audit trail — reviewer initials on a checklist
  • Compliance exposure when borrower overcharges go undetected
  • Coverage gaps — no safety net when auditor is on vacation

⚠️ Compliance Stakes

If recording fees on the Closing Disclosure do not match what was actually charged on recorded instruments, a borrower refund is legally required. Missing this is not a process failure — it is a compliance failure. The current manual process creates systematic exposure at scale.

🔑 The Secret Weapon: Stacking Order as Schema

Dr. BoB is not doing blind OCR on a mystery PDF. Because the stacking order is known and deterministic, Dr. BoB knows exactly what document is at every position before it opens the file.

This makes extraction highly reliable — not guesswork, not pattern matching against unknown layouts. Structured, rule-driven, repeatable.

📊 Two-Phase Validation Model

  • Phase 1 — Intra-bundle: Docs cross-reference each other (CD vs FSS vs Recorded instruments)
  • Phase 2 — System of record: Agreed values confirmed against BytePro DB as final truth anchor

✅ What the Auditor Sees

  • Email notification with flagged exceptions only
  • All passing docs automatically dismissed — never need human eyes
  • Specific finding: "CD shows $90, Warranty Deed shows $64 — mismatch"
  • Clear remediation path: "Refund required — notify Settlement Agent"
  • Timestamped audit trail generated per run — defensible compliance record

💬 The User Experience Shift

Before: Open PDF → read every page → mentally compare → flag anything wrong → repeat per loan

After: Open email → review flagged exceptions only → dismiss, act, or escalate → done

Phase 2 Design
R1
CD vs. Final Settlement Statement Cross-Reference
Extract Government Recording Fees from CD (Doc 1) and FSS (Doc 4). All line item amounts must match. Validates fees disclosed to borrower match fees actually charged.
🚨 Mismatch → "Recording fees on CD do not match FSS amounts"
R2
FSS vs. Recorded Warranty Deed
Extract recording fee from FSS (Doc 4). Extract fee stamp from Recorded Warranty Deed (Doc 5) — Dr. BoB scans: top right page 1 → last page → attached page. Amounts must match.
🚨 Mismatch → "Warranty Deed fee differs from FSS — borrower may be overcharged. Refund required."
R3
FSS vs. Recorded Deed of Trust / Security Instrument
Extract recording fee from FSS (Doc 4). Extract fee stamp from Recorded DOT (Doc 6) — Dr. BoB scans: right corner or attached page. Amounts must match.
🚨 Mismatch → "DOT recording fee differs from FSS — borrower may be overcharged. Refund required."
R4
Bundle Completeness Check (runs before OCR)
Validates all 6 required documents are present in the bundle before any OCR begins. A missing document means the reconciliation is incomplete — not a pass.
⚠️ Missing doc → "Recorded Warranty Deed not found — request from Settlement Agent via Parties screen in Byte"

🏦 BytePro as Final Truth Anchor

After intra-bundle cross-reference passes, Dr. BoB validates the agreed fee values against BytePro DB as the system of record. Two-phase: docs must agree first — then BytePro confirms.

Notification Model

🔑 How Actor Routing Works

The login identity at bundle initiation is the routing key for the entire findings workflow. No manual assignment. No "who owns this?" ambiguity. The system already knows.

📋 Notification Layers

  • Layer 1 — Primary: Initiating user — always automatic
  • Layer 2 — Coverage: Bundle-type-scoped department inbox (configurable)
  • Layer 3 — Escalation: Unactioned findings → supervisor (Phase 2 roadmap)

🏖️ The Vacation Problem — Solved

A critical finding identified on a loan where the initiating auditor is on vacation for 2 weeks cannot sit unattended — compliance and borrower refund timelines don't wait.

The department coverage inbox ensures every finding is visible to the full team, regardless of individual availability.
